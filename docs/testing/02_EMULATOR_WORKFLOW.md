# 02 — Emulator Workflow
**Phase:** 2 — Firebase Dev Bootstrap
**Status:** READY — All emulators configured. Start command: `npx -y firebase-tools@latest emulators:start --project crowdbeats-v2-dev`

---

## Purpose

The Firebase Local Emulator Suite is the **primary development environment** for
Crowdbeats V2. No cloud Firestore, Auth, or Functions are called during local development.
This means:
- No billing accrues during development
- No real user data is created
- No Stripe live mode is ever triggered
- CI pipelines run against emulators, not cloud

```powershell
# From the monorepo root — starts all configured emulators
```

| Emulator | Port | UI URL |
|---|---|---|
| Emulator Suite UI | 4000 | http://localhost:4000 |
| Firebase Auth | 9099 | http://localhost:4000/auth |
| Cloud Functions | 5001 | http://localhost:5001 |
| Firestore | 8080 | http://localhost:4000/firestore |
| Cloud Storage | 9199 | http://localhost:4000/storage |
| Hosting | 5002 | http://localhost:5002 |

All ports are in `firebase.json` under `emulators`. Change them there if conflicts exist.

## Connecting the Web App to Emulators

The `apps/web/.env.local` file sets `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` by default.

In Phase 5, `apps/web/lib/firebase/app.ts` will be extended with emulator connections:

```typescript
// Phase 5 additions to apps/web/lib/firebase/auth.ts
import { connectAuthEmulator, getAuth } from 'firebase/auth';
import { firebaseApp } from './app';

const auth = getAuth(firebaseApp);

if (process.env.NEXT_PUBLIC_USE_FIREBASE_EMULATOR === 'true') {
  connectAuthEmulator(auth, 'http://localhost:9099', { disableWarnings: true });
}
```

```typescript
// Phase 5 additions to apps/web/lib/firebase/firestore.ts
import { connectFirestoreEmulator, getFirestore } from 'firebase/firestore';
import { firebaseApp } from './app';

const db = getFirestore(firebaseApp);

if (process.env.NEXT_PUBLIC_USE_FIREBASE_EMULATOR === 'true') {
  connectFirestoreEmulator(db, 'localhost', 8080);
}
```

## Connecting Flutter to Emulators

In Phase 5, `apps/mobile/lib/firebase/firebase_options.dart` (generated by FlutterFire CLI)
will be augmented with emulator routing in `main.dart`:

```dart
// Phase 5 addition to apps/mobile/lib/main.dart
import 'package:firebase_auth/firebase_auth.dart';
import 'package:cloud_firestore/cloud_firestore.dart';
import 'package:firebase_storage/firebase_storage.dart';

Future<void> configureEmulators() async {
  const useEmulator = bool.fromEnvironment('USE_FIREBASE_EMULATOR', defaultValue: false);
  if (useEmulator || kDebugMode) {
    await FirebaseAuth.instance.useAuthEmulator('localhost', 9099);
    FirebaseFirestore.instance.useFirestoreEmulator('localhost', 8080);
    await FirebaseStorage.instance.useStorageEmulator('localhost', 9199);
  }
}
```

Run with emulator flag: `flutter run --dart-define=USE_FIREBASE_EMULATOR=true`

## Emulator Seed Data Policy

> [!IMPORTANT]
> All emulator seed data must be **deterministic** and **fictitious**.
> Real names, emails, UIDs, or payment data must never appear in seed fixtures.

Phase 3 will create `firebase/emulator-data/` with the following seed sets:

| Seed Set | Contents |
|---|---|
| `auth-users.json` | 5 fictitious test users per persona type (fan, musician, band-member, venue-manager) |
| `firestore.json` | 3 artist profiles, 2 active stage sessions, 10 tips (all integer amountCents) |
| `storage/` | Placeholder images (solid-color PNGs, no real photos) |

**Fictitious user naming convention:**
- UIDs: `test-fan-001`, `test-musician-001`, etc.
- Emails: `fan001@crowdbeats-emulator.test`
- Names: `Fan User 1`, `Musician User 1`, etc.

## Running the hello Callable Against the Emulator

Phase 2 includes a `hello` callable for emulator verification:

```typescript
// From a browser console or test script with Firebase client SDK
import { getFunctions, connectFunctionsEmulator, httpsCallable } from 'firebase/functions';
import { firebaseApp } from '@/lib/firebase/app';

const functions = getFunctions(firebaseApp, 'us-central1');
connectFunctionsEmulator(functions, 'localhost', 5001);

const hello = httpsCallable(functions, 'hello');
const result = await hello({ name: 'Crowdbeats' });
console.log(result.data); // { ok: true, data: { message: '...', phase: '...' }, requestId: '...' }
```

## CI Pipeline — Emulator Tests

The `.github/workflows/ci.yml` skeleton will be extended in Phase 3 to:

1. Start emulators with `--only firestore,auth,functions,storage`
2. Wait for emulator readiness via `--wait`
3. Run Firestore security rules tests (`firebase emulators:exec`)
4. Run Functions integration tests against emulator endpoints
5. Stop emulators

```yaml
# Phase 3 addition to ci.yml
- name: Start Firebase Emulators
  run: |
    npx -y firebase-tools@latest emulators:exec \
      --only firestore,auth,functions,storage \
      --project crowdbeats-v2-dev \
      "npm run test:emulator --workspace=apps/functions"
```

## Emulator Data Lifecycle

```
Dev machine (local)
  └── firebase emulators:start
        └── Loads firebase/emulator-data/ (seed)
              └── Developer modifies data via UI or tests
                    └── firebase emulators:export (save new seed)
                          └── git commit firebase/emulator-data/ (approved fixture)
```

**Rule:** Only fictitious seed data is committed. Never export and commit a session
that contained real user data, real payment amounts, or real names.

## Troubleshooting

| Issue | Solution |
|---|---|
| Port conflict | Change port in `firebase.json` emulators block |
| Auth emulator not routing | Check `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` in `.env.local` |
| Firestore permission denied | Verify emulator is running; check `connectFirestoreEmulator()` called |
| Functions not found | Ensure `npm run functions:build` ran before emulator start |
| Flutter not routing to emulator | Pass `--dart-define=USE_FIREBASE_EMULATOR=true` to `flutter run` |
| Windows port in use | Run `netstat -ano | findstr :<port>` then `taskkill /PID <pid> /F` |
